# TickTrack — памятка для Claude

Трекер времени для YouTrack в строке меню macOS. Источник требований — `docs/SPEC.md`. Отступления от ТЗ записываются в `docs/decisions.md`, идеи сверх ТЗ — в `docs/ideas.md` по MoSCoW (правила ведения — в начале файла).

## Команды

- Сборка: `swift build`
- Тесты: `scripts/test.sh`. Голый `swift test` без Xcode не находит модуль `Testing`, скрипт добавляет нужные флаги.
- Приложение: `scripts/build-app.sh [debug]`, затем `open build/TickTrack.app`.
- Демо без сервера: `TICKTRACK_DEMO=1 swift run`.
- Проверка вёрстки без доступа к экрану: `TICKTRACK_DEMO=1 TICKTRACK_SNAPSHOTS=<папка> .build/debug/TickTrack` отрисует экраны в PNG (светлая и тёмная тема) и завершится. Стекло и разделители в таком рендере не видны, это нормально.

## Окружение

Сборка и тесты рассчитаны на Command Line Tools без Xcode (Swift 6.2, SDK macOS 26): `xcodebuild` и `xcstringstool` не используются, String Catalog не компилируется (см. `docs/ideas.md`, I-7).

## Устройство

- `TickTrackCore` — чистая логика без UI. Любое правило учёта (отрезки, округление, простой, перенос, очередь) пишется здесь как метод `TrackerState` и покрывается тестом.
- Новые поля `TrackerState` объявлять Optional (или писать свой `init(from:)`): синтезированный Decodable падает на отсутствующем ключе, и старый `state.json` сбросится вместе с учётом. Пример — `storedExternal`, тест — `stateSavedBeforeExternalItemsStillLoads`.
- `AppModel` (`@Observable`) — время, система (простой, сон, блокировка), YouTrack, окна. Менять `state` только через методы модели или `mutateState`, после изменения состояние сохраняется.
- Таргет приложения собирается с `defaultIsolation(MainActor)`.
- Меню — своя `NSPanel` (`MenuBarController`), а не `MenuBarExtra`; карточки списания — `CardPanelController`. Обе панели неактивирующиеся.
- Подтверждения «Списано / Изменено / Удалено в YouTrack» показываются только после ответа сервера (`AppModel.sync`).
- Картинки (иконка, кот в строке меню, анимация) и что поменять для своей сборки — в README, разделы «Графика» и «Своя сборка». Если меняются файлы в `Support/`, их имена или идентификаторы приложения, эти разделы обновляются вместе с кодом.

## Соглашения

- Заметные изменения записывать в `CHANGELOG.md` в раздел готовящейся версии, на русском, для людей. Версию в `Support/Info.plist` меняет только выпуск (см. README → «Версии»).
- Интерфейс и комментарии в коде — на русском, тексты берутся из SPEC.
- Строки интерфейса пишутся как ключи локализации (`Text("…")`), данные из YouTrack — через `Text(verbatim:)`.
- Работа идёт в ветке `develop`, в `main` — только выпуски (см. README → «Ветки»). Перед коммитом проверять, что текущая ветка — `develop`.
- Личные настройки окружения (почта для коммитов, что установлено на машине) — в `CLAUDE.local.md`, он не попадает в git.
